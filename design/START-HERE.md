# بردگیم‌ورس — بستهٔ تحویل دیزاین سیستم به تیم فنی (v1.3)

این پوشه هر چیزی است که برای پیاده‌سازی دیزاین سیستم BGV روی کد `boardgame-club` لازم است. بسته برای کار با **Claude Code** بهینه شده است:

- **قانون‌ها** همیشه در کانتکست Claude هستند.
- **هوک‌ها** هر تغییری را که از دیزاین سیستم بیرون بزند همان لحظه رد می‌کنند.
- **QA نهایی** با یک دستور اجرا می‌شود.

## محتوای بسته
| مسیر | چیست |
|---|---|
| `repo/` | هر چیزی که باید در ریشهٔ ریپو کپی شود (ساختارش دقیقاً مثل ریپو است). |
| `repo/design/system/` | خود دیزاین سیستم: توکن‌ها، CSS همهٔ کامپوننت‌ها، پیاده‌سازی مرجع React، تایپ‌ها، راهنمای ۹۴ کامپوننت و مستندات. |
| `repo/design/reference/` | ۱۱۵ صفحهٔ طراحی‌شده: تصویر هر صفحه در هر عرض (۱۴۴۰، ۱۰۰۰، ۳۹۰)، HTML دقیق، نقشهٔ صفحه به route (`screens.json`)، تصویر هر کامپوننت. |
| `repo/design/brand/` | کیت کامل برند (لوگو، نشان، آیکن اپ، تصویر شبکه‌های اجتماعی، برندبوک PDF) و **فاویکن نهایی** (`favicon-production/`). قوانین استفاده در `LOGO-USAGE.md` است. |
| `repo/design/CLAUDE.design-system.md` | قوانین اجباری، که Claude Code همیشه می‌خواند. |
| `repo/design/IMPLEMENTATION-PLAN.md` | ترتیب کار، فاز ۰ تا ۷، با چک‌لیست و فهرست صفحه‌های هر route. |
| `repo/design/MIGRATION-MAP.md` | نگاشت توکن‌ها و فایل‌های قدیمی (VibeFarsi) به توکن‌ها و فایل‌های جدید. |
| `repo/scripts/ds-check.mjs` | گارد ایستا: رنگ هاردکد، radius، سایه و فونت خارج از توکن، کلاس‌های پالت Tailwind، چپ و راست فیزیکی، توکن و ایمپورت قدیمی، لوگوی بازکشیده و… |

| `repo/.claude/` | اسکیل `bgv-design-system`، دستورهای `/bgv-implement` و `/bgv-qa`، ایجنت مستقل `bgv-design-qa`. |
| `repo/.github/workflows/design-system.yml` | چک CI روی هر PR. |
| `LINKS.md` | لینک دیزاین سیستم، صفحه‌ها، سند تصمیم‌ها و ریپو. |

## نصب (یک بار برای هر توسعه‌دهنده)
1. محتوای `repo/` را در ریشهٔ ریپو کپی کنید (ادغام با فایل‌های موجود؛ چیزی پاک نمی‌شود).
2. در ریشهٔ ریپو اجرا کنید:
   ```
   node design/install.mjs
   ```
   این دستور چهار کار انجام می‌دهد:
   - هوک‌ها را در `.claude/settings.json` ادغام می‌کند؛
   - خط `@design/CLAUDE.design-system.md` را به `CLAUDE.md` اضافه می‌کند؛
   - اسکریپت‌های `ds:*` را به `package.json` اضافه می‌کند؛
   - بدهی فعلی را در `design/ds-baseline.json` ثبت می‌کند.
3. چون `/.claude/` و `/CLAUDE.md` در این ریپو gitignore هستند، هر توسعه‌دهنده یک بار مرحلهٔ ۲ را اجرا می‌کند. بقیهٔ فایل‌ها (`design/`, `scripts/`, `e2e/`, workflow) را commit کنید.

## کار با Claude Code
- شروع کار:
  ```
  /bgv-implement phase-0
  ```
  بعد فازها را به ترتیب جلو ببرید (`phase-1` … `phase-6`)، یا برای یک صفحه یا گروه: `/bgv-implement Home-Desktop` یا `/bgv-implement play`.
- **اجبار به استفادهٔ کامل از دیزاین سیستم:**
  - **هوک ویرایش:** بعد از هر ویرایش فایل UI، `ds-check` همان فایل را بررسی می‌کند. اگر تخلف تازه‌ای اضافه شده باشد، خطا را به Claude برمی‌گرداند تا همان لحظه درستش کند.
  - **هوک Stop:** قبل از اینکه Claude کار را تمام کند، همهٔ فایل‌های تغییرکرده یک بار دیگر بررسی می‌شوند.
  - **CI:** روی هر PR جلوی اضافه شدن بدهی را می‌گیرد. بدهی قبلی فقط می‌تواند کم شود (`pnpm ds:ratchet`).
  - **پایان مهاجرت:** در فاز ۶ CI روی حالت `--strict` می‌رود، یعنی صفر خطا.
- **QA نهایی (تریگر):**
  ```
  /bgv-qa
  ```
  این دستور سه بخش دارد:
  1. **گارد ایستا** در حالت strict.
  2. **عکس از اپ واقعی:** همهٔ صفحه‌ها در هر عرض و تم عکس گرفته می‌شوند و DOM ممیزی می‌شود. این ممیزی رنگ و radius خارج از توکن، فونت، اسکرول افقی، بیرون‌زدگی از کادر، چسبیدن متن به کادر، ارقام لاتین و شِل درست را بررسی می‌کند.
  3. **بازبینی بصری مستقل:** برای هر گروه صفحه یک ایجنت مستقل تصویر طراحی و اپ را کنار هم مقایسه می‌کند.

  خروجی در `design/qa/index.html` (گزارش کنار‌به‌کنار) و `design/qa/VERDICT.md` (نتیجهٔ PASS/FAIL و لیست ایرادها) نوشته می‌شود.
  - صفحه‌های میز بازی به میز زنده نیاز دارند. متغیر `BGV_QA_TABLES` را تنظیم کنید؛ جزئیاتش در `.claude/commands/bgv-qa.md` است.

## تصمیم‌های کلیدی (خلاصه)
- **گوشه‌ها:** اولویت با برندبوک است: ۸ برای دکمه و فیلد، ۱۲ برای کاشی داخلی، ۲۰ برای کارت، ۲۸ برای میز و شیت.
- **تم:** کلی‌مورفیسم حفظ می‌شود. تم تیره پس‌زمینهٔ ذغالی (#191B1A) دارد و کارت‌ها سبز تیره‌اند.
- **دکمه‌ها:**
  - primary برای ادامه دادن (پیوستن، آماده‌ام، یه دست دیگه)؛
  - secondary برای کارهای خنثی، از جمله «رد»؛
  - ghost برای کارهای کم‌اهمیت؛
  - leave برای «ترک میز»، «انصراف از صف» و «خروج از حساب»؛
  - danger فقط برای کارهایی که چیزی را پاک می‌کنند.
- **سکه:** طلایی فلزی واقعی.
- **صندلی‌ها:** ۱۰ رنگ، همیشه همراه با شکل و نام.
- **نام بازی‌ها:** نام فارسی اصلاح‌شده، کنار عنوان لاتین.
- **بازی‌ها:** صفحهٔ هر بازی همان رابط واقعی کد است و بازطراحی نمی‌شود. دیزاین سیستم فقط قاب دور آن را تعریف می‌کند: نوار بازی، داشبورد بازیکن‌ها، قرص نوبت، پلاک‌ها، دکمه‌های پایین و چت.
- **ساعت:** وقتی اتصال خود کاربر قطع می‌شود، حالت `stale` نمایش داده می‌شود. حالت `frozen` فقط برای قطعی سرور است.
- **ریسپانسیو:** از ۱۲۰۰ به بالا سایدبار کامل، بین ۹۰۰ و ۱۱۹۹ سایدبار آیکنی، و زیر ۹۰۰ نوار بالا و داک.
- **هشدار زمان:** صدا و لرزش داخل اپ، و وب‌پوش. پیامک نداریم.

داده، عددها و قوانین از کد می‌آیند؛ متن‌های داخل طرح‌ها نمونه‌اند. هر جا طرح با کد نخواند، گزارش بدهید.
