## تصمیم‌های اصلی (قطعی)

1. **مثل BGA:** هر چیزی روی صفحهٔ خودش و در اندازهٔ واقعی‌اش؛ هنر فلت ناشر، بی‌تغییر. **کارت‌ها تصویر کامل ناشرند** و با HTML بازسازی نمی‌شوند. هیچ قطعه، کارت یا نشانی با CSS یا یونی‌کد ساخته نمی‌شود؛ اگر قطعه‌ای نیست، از دیزاین بخواهید.
2. **چیدمان دسکتاپ (ترتیب BGA):** ریل ۳۶۰px سمت راست (`position: sticky`): بالایش **داشبورد پارامترها** (زوم −/+، راهنما، تنظیمات؛ اکسیژن، دما، اقیانوس، نسل)، بعد پنل بازیکن‌ها به ترتیب نوبت و گزارش. ستون بازی از بالا به پایین: نوار کنش (چسبان)، **دست شما** (بالای نقشه)، **صفحهٔ تارسیس بدون قاب مسیر رتبه** («دسته/دورریز» و «نسل» روی گوشهٔ صفحه)، و **محوطهٔ بازیکن‌ها** (اول خودتان، بعد به ترتیب نوبت). صفحه اسکرول می‌خورد. چت ستون ندارد و از نوار بازی به شکل شیت کناری باز می‌شود.
3. **دست شناور (تنظیم میز، مثل `handplace=floating` در BGA):** به‌جای بخش بالای نقشه، کشوی ثابت پایین صفحه. پیش‌فرض: بالای نقشه. تنظیم محلی بازیکن.
4. **دست مثل BGA:** کارت‌ها همان‌طور که هستند؛ قابل بازی‌ها حلقهٔ کهربایی؛ **هزینه زیر کارت نوشته نمی‌شود و کارت غیرقابل بازی کم‌رنگ نمی‌شود** (فقط `aria-disabled` و دلیل در `title`/زوم). هزینهٔ بعد از تخفیف در داک پرداخت دیده می‌شود.
5. **پنل بازیکن مثل BGA:** عدد اصلی **امتیاز کل فعلی** است (`score().total`، دایرهٔ قهوه‌ای)؛ TR جدا روی نشان TR؛ کارت در دست؛ لوگوی شرکت (`art/markers/corp-logos/`)؛ ۶ منبع با موجودی روی پلاک تیره وسط آیکون و تولید سفید روی قهوه‌ای زیرش؛ نشان‌ها **فقط آیکون** (`art/markers/tags/`) با عدد روی پلاک تیره. نمایش «فقط TR» (تنظیم BGA) فعلاً نیست.
6. **محوطهٔ بازیکن مثل BGA، بدون صفحهٔ بازیکن:** سر روی پلاک روشن **«خاک مریخ»** (`#F6ECDD` ← `#E4CDAE`، در همهٔ تم‌ها) با نام، لوگو، امتیاز، TR، دست، هر منبع با جعبهٔ سفید موجودی و نوار قهوه‌ای تولید، نشان‌ها ۴۰px؛ بعد بخش‌های **ستاد** (شبکه)، **خودکار**، **اثرها**، **کنش‌ها**، **رویدادها** (دسته؛ رویدادها پیش‌فرض بسته). هر بخش باز/بسته‌شو و با ≡ بین شبکه و دسته.
7. **رنگ بازیکن = رنگ مکعب او** (قرمز، آبی، سبز، زرد، سیاه به ترتیب صندلی، همان `renderer.css` امروز). مکعب سفید: اکسیژن و دما.
8. **نقطه‌ها و دکمه‌های روی صفحه:** پروژه‌های استاندارد، پلاک‌های نقطهٔ عطف و جایزه روی خود صفحهٔ تارسیس زدنی‌اند و همان‌ها در نوار کنش هم هستند.
9. **کنش‌ها از موتور:** دکمه‌ها از `legalActions()`، هزینه از همان، دلیل غیرفعال از کد خطای `validateAction`/`playError`، جای مجاز از `respond.options`. رندرر قانون را تکرار نمی‌کند.
10. **برگشت فقط پیش از «تأیید».** انتخاب کارت، پرداخت، انتخاب پروژه/پلاک تا «تأیید» موقت‌اند. بعد از تأیید برگشت نیست. **تأیید خودکار نداریم.** تصمیم‌هایی که بعد از تأیید از موتور می‌آیند برگشت ندارند اما تا «تأیید» خودشان می‌شود گزینهٔ دیگری زد.
11. **۱ یا ۲ کنش در نوبت:** بعد از کنش اول «پایان نوبت» یا کنش دوم. «پاس» یعنی بیرون تا آخر نسل و همیشه تأیید می‌خواهد.
12. **مرحله‌های هم‌زمان** (نسل ۱، درفت، پژوهش): ناحیهٔ دست ناحیهٔ انتخاب می‌شود؛ کنار هر بازیکن «آماده»/«در حال انتخاب»؛ بعد از «تأیید» عوض نمی‌شود.
13. **گوشی ۱۰۰٪ قابل بازی:** سربرگ‌های مریخ / دست / بازیکنان، نوار پایین با «کنش‌ها» و شیت همهٔ کنش‌ها، داک برای پرداخت و تصمیم‌ها، زوم خودکار روی خانه‌های مجاز.

## HUD و `publicSummary` (در چارچوب قرارداد DS v2.1، بدون تغییرش)

قرارداد DS (`design/system/docs/6-developer-contract.md`) را عوض نکنید. همهٔ دادهٔ اضافهٔ ترافورمینگ در فیلد اختیاری `detail` هر صندلی است که قرارداد DS خودش پیش‌بینی کرده:

```ts
seats[k] = {
  seat, primary: { label: 'امتیاز', value: score(s, k).total },
  stats: [ { key: 'tr', label: 'رتبه', value: p.tr }, { key: 'mc', label: 'مگاکردیت', value: p.res.mc, delta: p.prod.mc },
           { key: 'hand', label: 'کارت', value: p.hand.length }, { key: 'plants', label: 'گیاه', value: p.res.plants, delta: p.prod.plants } ], // ≤ ۴، مثل DS
  handCount: p.hand.length, status: 'passed' | 'done' | 'winner' | undefined,
  badges: k === s.firstPlayer ? [{ key: 'first', label: 'نفر اول' }] : [],
  detail: { corp: p.corp, tr: p.tr, res: p.res, prod: p.prod, tags: { building: n, …, event: n }, cities: n, greeneries: n } // مخصوص ترافورمینگ
}
shared = [generation, temperature, oxygen (max 14), oceans (max 9), deck, discard]
```

- سر پنل (آواتار، نام، لیگ، ساعت، وضعیت) همان کارت `bgv-pcard` پوستهٔ DS است.
- **بدنهٔ پنل** (منابع، تولید، نشان‌ها، لوگو، امتیاز، TR) را خود رندرر ترافورمینگ از `detail` می‌سازد و داخل جای جزئیات کارت (`bgv-pcard__detail`) می‌گذارد. اگر پوستهٔ میز هنوز راهی برای بدنهٔ ساخت بازی ندارد، یک نقطهٔ اتصال **اختیاری و افزودنی** در کلاینت بازی اضافه شود (مثلاً `SeatDetail` در باندل بازی). بازی‌هایی که آن را ندارند همان کارت امروز را می‌گیرند. بستهٔ گایا هم همین نیاز را دارد (درآمد و قدرت): یک سازوکار برای هر دو، هر کدام زودتر رسید آن را بسازد، دیگری استفاده کند.
- نمای کامل: `TM-Components` §۲ و `COMPONENTS.md §۲`.

## هماهنگی با DS v2.1 و بستهٔ گایا (بدون تداخل)

DS v2.1 و بستهٔ گایا هنوز در ریپو اعمال نشده‌اند. این بسته طوری نوشته شده که به هر ترتیبی نصب شود (DS ← ترافورمینگ، یا DS ← گایا ← ترافورمینگ) چیزی را خراب نکند:

| موضوع | قاعده |
| --- | --- |
